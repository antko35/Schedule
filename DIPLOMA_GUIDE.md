## 2. ФОРМАТИРОВАНИЕ — СТИЛИ WORD

Все правки в `Диплом.docx` делаются **через существующие стили шаблона**.
Никогда не применять ручное форматирование поверх стилей.

### Таблица стилей (styleId → назначение)

| styleId в XML | Название стиля | Когда использовать |
|---|---|---|
| `1` | Заголовок 1 (heading 1) | Заголовок раздела: «1 НАЗВАНИЕ РАЗДЕЛА» |
| `2` | Заголовок 2 (heading 2) | Заголовок подраздела: «1.1 Название подраздела» |
| `3` | Заголовок 3 (heading 3) | Заголовок пункта: «1.1.1 Название пункта» |
| `a1` | Normal | Основной текст абзацев |
| `a0` | Сложное перечисление | Нумерованный список (арабские цифры, прописная буква, точка в конце) |
| `a` | Простое перечисление | Список с тире (строчная буква, точка с запятой в конце) |
| `a7` | List Paragraph | Вложенные списки с буквой+скобкой: «а)», «б)» |
| `af0` | Подпись рисунка | Подпись под рисунком: «Рисунок X.Y – Название» |
| `af2` | Подпись таблицы | Заголовок над таблицей: «Таблица X.Y – Название» |
| `a5` | Заголовок раздела | Заголовки типа «ВВЕДЕНИЕ», «ЗАКЛЮЧЕНИЕ» (прописные, по центру) |
| `a6` | название раздела «РЕФЕРАТ» | Заголовки «РЕФЕРАТ», «СОДЕРЖАНИЕ», «СПИСОК...» |

### Параметры страницы (заданы в шаблоне, не менять)
- Поля: левое 30 мм, правое 15 мм, верхнее 20 мм, нижнее 27 мм
- Шрифт: Times New Roman 14 пт
- Межстрочный интервал: множитель 1,15
- Абзацный отступ: 1,25 см
- Выравнивание: по ширине

### Правила оформления заголовков
- Заголовок раздела (стиль `1`): **ПРОПИСНЫЕ БУКВЫ**, полужирный, 16 пт, отступ 12 пт сверху и снизу, каждый раздел — с новой страницы
- Заголовок подраздела (стиль `2`): Строчные (кроме первой), полужирный, 14 пт, отступ 12 пт сверху и 6 пт снизу
- Заголовок пункта (стиль `3`): Строчные, полужирный, 14 пт, отступ 6 пт сверху
- Заголовки «ВВЕДЕНИЕ», «ЗАКЛЮЧЕНИЕ» и т.д.: стиль `a6`, прописные, по центру, 16 пт

### Правила оформления рисунков
- Рисунок размещается по центру, без абзацного отступа
- Отделяется от предшествующего текста одной пустой строкой
- Подпись (`af0`): «Рисунок X.Y – Наименование» (без точки в конце)
- Отступ под подписью: 12 пт
- Нумерация в пределах раздела: рисунок 1.1, 1.2, 2.1, 2.2 и т.д.
- В тексте ОБЯЗАТЕЛЬНА ссылка: «...приведено на рисунке 2.3» или «(см. рисунок 2.3)»

### Правила оформления таблиц
- Заголовок (`af2`) — над таблицей, выравнивание по левому краю таблицы: «Таблица X.Y – Название»
- Отступ перед заголовком: 12 пт сверху, 6 пт снизу
- Таблица отделяется от последующего текста пустой строкой
- Шрифт в таблице: 12 пт, одинарный интервал, без абзацного отступа
- Нумерация: таблица 1.1, 2.1 и т.д. (в пределах раздела)
- В тексте ОБЯЗАТЕЛЬНА ссылка: «...представлено в таблице 2.1» или «(см. таблицу 2.1)»

### Правила оформления перечислений
**Простое перечисление** (стиль `a`):
- Каждый элемент начинается с тире и абзацного отступа
- Элементы пишутся со строчной буквы
- Заканчиваются точкой с запятой (последний — точкой)

**Сложное перечисление** (стиль `a0`):
- Нумерованный список арабскими цифрами
- Каждый элемент с прописной буквы
- Заканчивается точкой

**Вложенное перечисление** (стиль `a7`):
- Элементы обозначаются «а)», «б)», «в)»
- Со строчной буквы, точка с запятой в конце

### Правила оформления листингов кода
- Шрифт Courier New или Consolas, 12 пт
- Одинарный межстрочный интервал
- Размер блока кода — не более 1 страницы в тексте (крупные фрагменты — в приложения)
- Нумерация как рисунок: «Рисунок 3.X – Листинг ...»

## 6. ТЕХНИЧЕСКАЯ ИНФОРМАЦИЯ О ПРОЕКТЕ (для раздела 3)

### Стек технологий
- **Платформа**: .NET 10, C#
- **Оркестрация (dev)**: .NET Aspire (`Schedule.AppHost`)
- **БД UserService**: PostgreSQL + Entity Framework Core
- **БД ScheduleService**: MongoDB (коллекции: UserScheduleRules, Schedules, Calendar)
- **БД UserManagementService**: MongoDB
- **Аутентификация**: Keycloak (realm: `schedule-service`, audience: `schedule-service`), JWT
- **Межсервисная синхронная коммуникация**: gRPC (`userService.proto`)
- **Межсервисная асинхронная коммуникация**: RabbitMQ (событие: пользователь добавлен в отдел)
- **Фоновые задачи**: Hangfire (в ScheduleService)
- **Observability**: OpenTelemetry через ServiceDefaults
- **Тесты**: xUnit + Moq + FluentAssertions

### Файловая структура проекта
```
src/
  UserService/
    UserService.API/          ← Controllers, Middleware, DI
    Application/              ← MediatR handlers, validators
    Domain/                   ← Entities, value objects
    Data/                     ← EF Core, Migrations
  ScheduleService/
    ScheduleService.API/      ← Controllers, Keycloak auth, Hangfire
    Application/              ← MediatR handlers
    Domain/                   ← Schedule, UserScheduleRule entities
    DataAccess/               ← MongoDB repositories
  UserManagementService/
    UserManagementService.API/← Controllers, RabbitMQ publisher
    Application/              ← MediatR handlers
    Domain/                   ← Department, Membership entities
    Infrastructure/           ← gRPC client, RabbitMQ
Schedule.AppHost/             ← Aspire orchestration
Schedule.ServiceDefaults/     ← Shared OpenTelemetry, health checks
tests/
  UserServiceTests/
  ScheduleServiceTests/Application/
  UserManagementTests/ClassLibrary3/
```

### Workflow создания расписания
1. POST `/User` на UserManagementService (5003) — создать пользователя
2. POST `/Department` на UserManagementService — создать отдел
3. POST `/Department/addUserToDepartment` — добавить пользователя; автоматически создаётся `UserScheduleRule` в MongoDB ScheduleService
4. PUT правила генерации через ScheduleService (5002): HoursPerMonth, StartWorkDayTime, EvenDOM/UnEvenDOM, EvenDOW/UnEvenDOW
5. POST `/Schedule` — ручное создание или Hangfire-job автоматически генерирует расписание

### Алгоритм генерации (для раздела 3.3)
```
Для каждого дня месяца:
  if EvenDOM && день чётный → смена 1
  if UnEvenDOM && день нечётный → смена 2
  if EvenDOW && (пн,ср,пт) → смена 1
  if UnEvenDOW && (вт,чт) → смена 2
  Пропустить праздники (коллекция Calendar)
  Суммировать часы, не превышать HoursPerMonth
```

### Алгоритм субботних дежурств
```
1. Выбрать субботнее дежурство (5 часов)
2. Выбрать N рабочих дней для компенсации
3. Для каждого выбранного дня: длительность смены -= 1 час
4. Пересчитать суммарный баланс часов
5. Проверить соответствие норме
```
